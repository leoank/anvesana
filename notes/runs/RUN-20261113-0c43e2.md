## Notes

`commit` is the anvesana tree at the time; the running system came from neusis's pinned
anvesana input (kernel and spi-hid unchanged since 8ce8ce5).

Hand-run on curiosity (same boot as [[RUN-20261113-0c42vk]]), 2026-11-13 00:09-00:20, by Ank
as root with the laptop in hand or on the desk; iio-sensor-proxy stopped. `stream.sh` is the
still/tilt capture, `run.sh` the hysteresis test. On the stock kernel both get past the
power-on sleep by killing the writer (the sleep is interruptible; the power-on then finishes).

- iio:device1 samples: x, y, z as le:s16 in 32-bit slots, s64 timestamp, 24 bytes; scale
  0.0980665 (raw in 0.01 g). Hub DATA reports: report id 1 = this accelerometer, id 5 another
  sensor.
- Hysteresis 0.02 (default), 50 Hz: held still ~10 samples/s (104 in 10 s), tilting ~46/s
  (918 in 20 s); on the desk at boot IRQ 232 rose only 112 -> 144 in two hours.
- Hysteresis 0 written while the sensor was off: accepted (rc 0, reads 0.000000). On the desk,
  untouched: 515 samples in 10 s (~50/s, the set interval).
- GET_INPUT_REPORT: across the boot ~90 requests, no response of type 0x0b and no
  "Unexpected response report": the hub does not implement it. Each timeout made spi-hid reset
  the hub (iio-sensor-proxy's raw-read fallback: one every ~6 s).
- Fixes: udev rule `in_accel_hysteresis=0` for the hub's accelerometers (`nix/n1x.nix`);
  spi-hid no longer resets the hub when GET_INPUT_REPORT goes unanswered.
