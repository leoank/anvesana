## Notes

Windows on bbaum-pc-7, 2026-11-10, done by Ank: does the sensor hub need nvSCP.sys?

- The nvSCP device cannot be disabled: Device Manager offers no Disable, and
  `Disable-PnpDevice -InstanceId 'ACPI\NVDA8200\0'` fails with "Not supported"
  (HRESULT 0x8004100c). So the driver was kept from loading instead: service `nvSCP`
  `Start` = 4, then a reboot (booted 22:30:16).
- After the reboot (checked 2026-11-10 by Claude, read-only): `nvSCP` Stopped/Disabled,
  `ACPI\NVDA8200\0` Error, CM_PROB_DISABLED (problem code 22). `ACPI\MSFW1111\3`
  "SPI HID Device" OK; both "HID Sensor Collection V2" and the "Simple Device Orientation
  Sensor" OK.
- Ank: screen rotation still works.

So the hub runs without nvSCP: the SCP0 firmware answers hidspi.sys's reset and reports by
itself, and nothing nvSCP sends is needed for orientation. H1 is false. What differs on Linux
is on the host side of the hub: its interrupt (EINT 190 through GIO0) or the spi-hid driver.

To put Windows back: `run.ps1 -Step on` (Start = 3) and reboot.
