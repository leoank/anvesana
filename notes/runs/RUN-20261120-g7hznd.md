## Notes

Done 2026-11-20 14:10-14:55 on curiosity (curiosity ISO from neusis with anvesana 356ae30:
kernel 7.0.14-1022-nvidia, open driver 620.70.06; BIOS G2621NMS.10B, on AC), by hand: Ank ran
the root steps, I read the results. Follows [[RUN-20261118-hb8wfr]], which found that 615.78.08
never sent NPCF's only revision, 0x300; 620.70.06 does.

**Stock 620.70.06.** `nvidia-powerd` still quit at once: "DsmConfig3xStatic::
initializeWithRmControlCall failed with status: 0x00000056" (NV_ERR_NOT_SUPPORTED), then
"SBIOS support not found for NVPCF GET_SUPPORTED function". The kernel logged "nv_acpi_evaluate_
dsm_method: DSM data invalid!" and "Error during 0xc DSM subfunction 0x1! status=0x2"
(NV_ERR_BUFFER_TOO_SMALL). Cause, in the open driver's `client_resource.c`: for NVPCF 3.x
subfunctions 1-3 it divides the caller's buffer size by 4 before evaluating `_DSM`, and caps
the request at 4 KiB, so at most 1 KiB is left to receive into; NPCF function 1 returns 2,176
bytes. Upstream main and 620.73.04 still divide. The same size also sized `_DSM`'s Arg3, which
`nv_acpi_dsm_method` caps at 1 KiB. Fix: `nix/patches/nvidia-open-nvpcf3x-read-size.patch`
(no division; Arg3 capped at 1 KiB, which the firmware ignores for reads), commit 260cb0e.

**Patched 620.70.06**, swapped in without a reboot (built from neusis's curiosity config for
the booted kernel; `modprobe -r` also unloads `drm_ttm_helper` and `drm_display_helper`, which
must be loaded back before `nvidia-drm`, or the display stays off). The kernel errors are
gone. powerd now logs no error, yet still quits about a second after "DBus Connection is
established", exit 0, "Quit successfully"; GPU power limits stay N/A.

Under gdb (`rmctl.py`, output `powerd-gdb.out`) every RM control and alloc returns status 0.
powerd walks the whole NVPCF 3.x exchange (NV0000_CTRL_CMD_SYSTEM_NVPCF_GET_POWER_MODE_INFO,
0x13b): subfunction 0 gives 0x3f (all six); 1 the 2,176-byte init table, still no visible
header (likely encrypted; the 3.x interface defines a 32-byte password); 2 a 10-byte list
subscribing to id 0x3000; then three rounds of 3 (135 bytes, identical each time) and 4, and
finally 5 (critical status; RM does not copy its answer back), GPU detach, exit. Subfunction 3
holds four groups of three values that read as temperatures in 0.1 K: current 3135-3155
(40-42 °C) with limits 3331 (60 °C) and 3431 (70 °C), plus id 0x3000 = 3; no power limits.
powerd writes id 0x3000 = 3 back with subfunction 4 (in the DSDT, EC register 0x26A).

Why powerd stops is not in its logs. Its logger (file offset 0x130180) passes ERROR only;
`loglevel.py` relabels INFO, WARNING and the rest as ERROR, and the run still printed nothing
between "DBus Connection is established" and "Quit successfully", so the path that ends it does
not log. "Quit successfully" comes from the shutdown routine, not from the decision.
powerd also checks `/sys/devices/cpu_core` and `cpu_atom` (Intel hybrid paths, absent here) and
carries a "cpu not supported" path next to its Arm code, which remains a candidate.

Taking it further means tracing powerd's control flow by hand; stopped there. Whether Windows'
~61 W comes from Dynamic Boost at all, rather than MSI's power mode through the EC, is not
established. No `platform_profile` exists on Linux here.

The NVPCF exchange dumps (`tables/nvpcf/`) are vendor data and stay out of git.
