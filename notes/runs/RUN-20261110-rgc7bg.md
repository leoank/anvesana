## Notes

`sudo n1x-scp-peek` on bbaum-pc-7, live image ISO 0dbdca7c, sspm entry, boot 16ea71ed,
2026-11-10 22:13 (run by Ank). Read-only; output on SPARKDATA under
`bootlogs/bbaum-pc-7/scp-peek-20261110_221308/` (SRAM dumps are not in git).

- UEFI variables: `SCPCaliResult` and `NvSCPVar_0..9` are all absent, and no other variable
  name contains scp, cali or manufact. efivarfs shows the runtime variables that Windows'
  `ExGetFirmwareEnvironmentVariable` reads, so on Windows nvSCP finds none of them either:
  the start sequence's calibration and OEM-variable messages are most likely skipped there
  too. That weakens H1 as stated.
- Mailbox status at 0x100/0x104 of both 0x1AAA0000 and 0x1AAB0000: all zero. Doorbell page
  0x1AB20000: +0x0 and +0x4 read 0xFFFFFFFE, +0x8..+0x1C zero.
- SRAM 0x1A800000: Cortex-M firmware is loaded (vector table at 0: SP 0x6F5D8, reset 0x11105;
  Thumb code) and running: the word at +0x69540 went 0x1B53F -> 0x1C97F in 5 s, about
  1040 per second, a 1 kHz FreeRTOS tick; it was the only word that changed.
- Its strings show MediaTek SCP firmware (`./drivers/CM4/mt8901/...`, FreeRTOS) with a
  `spis-hid` SPI-slave HID driver and `middleware/hid_sensorhub` (handles "hid sensorhub
  rst." by sending a reset ack, then device and report descriptors over SPI), sensor drivers
  for lsm6dsv (accelerometer + gyroscope), lis2dw12 (accelerometer), bmm350 (magnetometer),
  tcs3430 (ambient light/colour), lid angle and hinge angle, and IPI handlers for the host
  (firmware version, probe SCP, log level, OEM customizable variable, calibration self-test,
  collect sensor data, NVPF messages, sensor info, set/get calibration result) in a
  "Windows system task". No formatted log lines were found in SRAM (format strings only).

So SCP0 is alive on Linux and carries the whole sensor hub; what it waits for before answering
the hub reset is still open.

## Reproduce
On the laptop, booted from the live image: `sudo n1x-scp-peek`. Hardware state (what the
firmware has done since boot) is not controlled; the tick count and some SRAM words differ
from run to run.
